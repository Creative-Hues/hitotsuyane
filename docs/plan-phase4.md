# フェーズ4の計画:掲示板

## 結論

- 下のタブに「掲示板」を足して5つにする([リスト][治療][交代][掲示板][人格])
- 掲示板の中に「板」(話題ごとの入れ物)を作れるようにし、その中で「スレッド」(話題)と「コメント」を書けるようにする
  - 「ホーム」の板は最初からあり、削除できない。ほかの板は追加・名前の変更・削除(確認つき)・並び替え(≡)ができる
  - 書くときは、最初に「いま書いている人格」を選ぶ。書いた人格は名前ラベルで出し、日時も出す
  - 書いたものは直せる・消せる。直したものには「編集済み」と出す
  - スレッドは、新しい書き込みがあった順に並べる
- 新しい書き込みには「新着」の印を付け、タブにも数(バッジ)を出す
- スレッドとコメントに「リアクション」(既読/理解/賛成/反対)を付けられる。誰が付けたかを名前ラベルで出す。選択肢は設定で変えられる
- 新しいデータを足すので、データベースの版を 8 → 9 に上げる。フェーズ2で作った「移行前の自動バックアップ」をそのまま使う。新しいデータはすべてバックアップに入れる
- 6つの段階に分ける。テスト版に反映する前と、main にマージする前に止まる(データの形が変わるので、マージの前に必ず声をかける)
- 決めてほしいことの答えは「決まったこと」の章にある

## 前提

- この計画は、`dev`(f24b092 フェーズ3。main と同じ)のコードを元にしている
- 画面の言葉の「人格」は、今と同じしくみ(`useTerm` の `t()`)で、設定した呼び方に置き換える
- 人格の名前を出すところは、名前ラベル(`AlterNameLabel`)を使う。選ぶための部品(大きな色のボタンなど)は今までどおり
- 並び替えは、すべて ≡ のドラッグで行う
- 日付の計算は `src/lib/period.ts` を通し、並び順・新着の判定などは純粋関数にしてテストを書く
- データは端末の中だけ。掲示板も、同じ端末を使う人格どうしで読み書きするもの(外への通信はしない)
- 保存の名前は `src/lib/appTarget.ts` を通す

## 1. タブを5つにする

```
[リスト][治療][交代][掲示板][人格]
```

- 掲示板のアイコンは、吹き出しの形(SVG をコードに直接書く。外から読み込まない)
- 5つになっても、長い呼び方(10文字)でタブの文字が崩れないようにする
  - 今は、入りきらない文字は「…」で切っている(「みんなのなかま…」)。5つにすると1つの幅が狭くなるので、文字を少し小さくするか、2行まで折り返すかを決める(確認したいこと1)
- 新着があるときは、掲示板のタブのアイコンの右上に、数の入った丸(バッジ)を出す(確認したいこと6)

## 2. 板・スレッド・コメント

### データ(新しいテーブル)

**板**

| 項目 | 説明 |
|---|---|
| id | 一意のID(ホームは決まった ID) |
| name | 名前(ホームは「ホーム」) |
| order | 並び順 |
| createdAt | 作成日時 |

**スレッド**

| 項目 | 説明 |
|---|---|
| id | 一意のID |
| boardId | どの板か |
| alterId | 書いた人格(「わからない」は null) |
| title | 題名(確認したいこと3) |
| body | 内容 |
| createdAt | 書いた日時 |
| editedAt | 直した日時(直していなければ null) |
| (保存しない) | いちばん新しい書き込みの日時は、スレッドとコメントの書いた日時から毎回計算する(「実装で決めたこと」) |

**コメント**

| 項目 | 説明 |
|---|---|
| id | 一意のID |
| threadId | どのスレッドへのコメントか |
| alterId | 書いた人格(「わからない」は null) |
| body | 内容 |
| createdAt | 書いた日時 |
| editedAt | 直した日時(直していなければ null) |

- どれも永続データ(自動では削除しない)

### 画面

```
掲示板
[ホーム][家のこと][病院のこと] [板の設定]   ← 板の切り替え
[＋ スレッドを立てる]
──────────────
● 新着  週末の予定について         ← 題名(新着の印)
  [人格A] 10/14 21:30 ・ コメント3件・最終 10/15 8:10
──────────────
  薬の時間を変えたい
  [人格B] 10/12 9:00 ・ コメント0件
```

- 掲示板タブを開くと、ホームの板のスレッドの一覧が出る。上の切り替えボタンで板を変える(アプリを開いている間は、最後に見ていた板を覚える。保存はしない)
- スレッドの一覧は、新しい書き込みがあった順(lastPostedAt の新しい順)
- スレッドを押すと、スレッドの画面(「‹ 戻る」あり)
  - いちばん上にスレッドの本文(書いた人格の名前ラベル・日時・「編集済み」・リアクション)
  - その下にコメントを古い順に並べる(1件ずつ、名前ラベル・日時・「編集済み」・リアクション)
  - 一番下に「＋ コメントを書く」
- 書くとき(スレッド・コメント)
  - 最初に「いま書いている人格」を選ぶ(非表示でない人格+「わからない」の大きな色のボタン。ToDo の記録と同じ見た目)。選んでから入力欄が出る
  - 内容が空なら「内容を入力してください」
- 直す・消す
  - 自分の書き込みを押すと(または「…」ボタンで)編集画面。直すと「編集済み」が付き、書いた日時は変えない
  - 消すときは確認を1回出す。スレッドを消すと、そのスレッドのコメントとリアクションも一緒に消える(確認文に「コメント○件も一緒に削除されます。」を足す)
  - 本人確認(バケットのような「人格A本人として」)の形にするか(確認したいこと4)

### 板の設定

- 「板の設定」で、板の追加・名前の変更・並び替え(≡)・削除ができる(一覧は `SPEC.md` 5.1 の共通ルール。非表示は作らない)
- ホームの板は削除できない(削除ボタンを押せなくし、「ホームの板は削除できません」と出す)。名前の変更と並び替えはできる(確認したいこと2)
- ほかの板と同じ名前は保存できない(「同じ名前の板があります」)
- 板を削除するときは確認を1回出す。中のスレッド・コメント・リアクションも一緒に消える(確認文に「スレッド○件も一緒に削除されます。」を足す)(確認したいこと2)

## 3. 新着

- 「新着」は、その書き込みを「まだ見ていない」こと(確認したいこと5)
  - アプリは、いま操作している人格を知らない。そのため「見た」は端末に1つだけ記録する(人格ごとには持たない)
  - スレッドの画面を開いたら、そのスレッドの書き込みを「見た」にする
- スレッドの一覧で、新着のあるスレッドに「● 新着」と出す
- 板の切り替えボタンにも、新着のある板に印を付ける
- 掲示板のタブに、新着のあるスレッドの数をバッジで出す(確認したいこと6)
- 自分で書いたものは新着にしない(書いたときに「見た」にする)

## 4. リアクション

```
[既読 2][理解 1][賛成][反対]   ← 押すと人格を選ぶ
既読:[人格A][人格B]
理解:[人格C]
```

- スレッドの本文と、コメントの1件ずつに付けられる
- 最初の選択肢:既読/理解/賛成/反対(確認したいこと7)
- 付けるとき:リアクションのボタンを押す → 人格を選ぶ(非表示でない人格。「わからない」は出さない。確認したいこと8)→ 付く
- もう一度、同じ人格で同じリアクションを選ぶと外れる(取り消し)
- 誰が付けたかを、リアクションごとに名前ラベルで並べる(人格の並び順)
- リアクションの選択肢は「リアクションの設定」で、追加・名前の変更・並び替え・削除ができる(確認したいこと7)
  - 使われている選択肢を削除するときの決まり(確認したいこと7)

### データ(新しいテーブル)

**リアクションの選択肢**:id・name・order・createdAt(最初の4つは決まった ID)

**リアクション**

| 項目 | 説明 |
|---|---|
| id | 一意のID |
| targetType | 'thread' / 'comment' |
| targetId | スレッドかコメントのID |
| kindId | リアクションの選択肢のID |
| alterId | 付けた人格 |
| createdAt | 付けた日時 |

- 同じ人格・同じ対象・同じリアクションは1つだけ

- データベースの版:8 → 9(更新のお知らせは「データの形が変わる」強めのもの。`DB_VERSION` を上げると自動で `version.json` に入る)

- 「見た」の記録(新着の判定)は、端末の設定としてバックアップに入れるか(確認したいこと9)
- 人格の削除(`SPEC.md` 3.1):スレッド・コメント・リアクションを書いた/付けた人格は、削除できない人格に数える(確認したいこと10)

## 確認したいこと

1. **タブが5つになったときの文字**:長い呼び方(例:「みんなのなかまたち」)のとき、どうしますか
   - 案A(おすすめ):文字を少し小さくして、入りきらない分は今と同じく「…」で切る(タブの高さは変えない)
   - 案B:2行まで折り返す(タブが少し高くなる)
2. **板**
   - ホームの板は、名前の変更もできないようにしますか(おすすめ:変えられないようにする。「ホーム」と決まっているほうが迷わないため)。並び替えでホーム以外を上に動かすことはできるようにしますか(おすすめ:ホームはいつも一番左に固定)
   - 板を削除するとき、中にスレッドがあっても削除できるようにしますか(確認文で件数を出す)。それとも、スレッドが1件もない板だけ削除できるようにしますか(おすすめ:スレッドがない板だけ。消えると戻せないため)
3. **スレッドの題名**:題名の欄を作りますか(おすすめ:作る。一覧で話題がすぐわかるため。空なら保存できない)。それとも、本文の1行目を題名の代わりにしますか
4. **直す・消すの守り方**:アプリは操作している人格を知らないので、ほかの人格の書き込みも直せてしまいます
   - 案A(おすすめ):バケットと同じく、本人確認の文を出す(「これは人格Aの書き込みです。人格A本人として、変更しますか?」)
   - 案B:ふつうの確認だけ(消すときだけ確認を出す)
5. **新着の意味**:端末に1つだけ「見た」を記録する形(人格ごとには持たない)でよいですか。人格ごとに「見た」を持つには、開くたびに「いま見ている人格」を選んでもらう必要があり、手間が増えます
6. **タブのバッジ**:数は「新着のあるスレッドの数」でよいですか(「新着の書き込みの数」より数が増えすぎないため)。99より多いときは「99+」にします
7. **リアクションの選択肢**
   - 最初の4つ(既読/理解/賛成/反対)は、絵文字なしの文字だけでよいですか
   - 「リアクションの設定」の入口は、掲示板の「板の設定」の画面の中に置く、でよいですか
   - 使われているリアクションの選択肢は、削除できないようにしますか(おすすめ:削除できない。名前の変更はできる。交代のきっかけと同じ)
8. **リアクションを付ける人格**:「わからない」でも付けられるようにしますか(おすすめ:付けられない。誰の反応かわからないと意味が薄いため)
9. **「見た」の記録とバックアップ**:「見た」の記録は、バックアップに入れますか(おすすめ:入れない。端末の設定と同じ扱い。読み込んだあとは、すべて「見た」にして新着を出さない)
10. **人格の削除**:スレッド・コメントを書いた人格、リアクションを付けた人格は、削除できない人格に数えてよいですか(おすすめ:はい。ほかの記録と同じ)

## 決まったこと(2026-10-14)

1. タブの文字は案A(少し小さくして、入りきらない分は「…」)
2. ホームの板は、名前の変更ができず、いつも一番左に固定する。板の削除は、スレッドが1件もない板だけ(ほかの人格の書き込みがまとめて消えないように)
3. スレッドの題名の欄を作る(空なら保存できない)
4. 直す・消すは案A(バケットと同じく、本人確認の文を出す)
5. 新着は、端末に1つだけ「見た」を記録する(誰が読んだかは、リアクションの「既読」で伝える)
6. タブのバッジは「新着のあるスレッドの数」。99より多いときは「99+」
7. リアクションの最初の4つは文字だけ。「リアクションの設定」の入口は「板の設定」の画面の中。使われている選択肢は削除できず、名前の変更はできる
8. 「わからない」ではリアクションを付けられない
9. 「見た」の記録はバックアップに入れない。読み込んだあとは、すべて「見た」にする
10. 書き込み(スレッド・コメント)・リアクションのある人格は、削除できない人格に数える

## 実装で決めたこと(細かいこと)

- スレッドの「いちばん新しい書き込みの日時」は保存せず、スレッドとコメントの書いた日時から毎回計算する(コメントを消したときに、ずれないようにするため)。直した日時(編集済み)は「新しい書き込み」に数えない
- 「新着」は、スレッドごとに「最後に見たときの、いちばん新しい書き込みの日時」を端末に記録して判定する。スレッドを開いている間に新しいコメントを書いたときも「見た」にする
- 直したものは新着にしない(「新しい書き込み」ではないため)
- 書き込む人格を選ぶ画面の見出しは「いま書いている人格は?」。リアクションを付ける人格を選ぶシートの見出しは「「既読」を付けるのは?」で、付けている人格には「✓」を付ける
- 板の設定の一覧では、ホームを一番上に ≡ なしで出す。ホームを開くと「ホームの板は、名前の変更・並び替え・削除はできません。」と出す
- 「板の設定」のボタンは、見出しの下に置く(見出しの行の右上は、フェーズ5の「?」のために空けておく)
