# フェーズ3の計画:受診の記録と、受診メモの表示の選択

## 結論

- 「受診した」ことを記録できるようにし、受診の履歴を一覧で見られるようにする
- 受診メモの「診察用の表示」で、「メモだけ」か「メモ+交代記録」か、期間(前回の受診日から/今月/今週/今日)を選べるようにする
  - 「交代記録」の部分は、要約(回数・出た人格・多いきっかけ)と、「誰から誰に」の詳しい一覧
- 新しいデータ(受診の記録・話した相手の選択肢)を足すので、データベースの版を 7 → 8 に上げる
  - フェーズ2で作った「移行前の自動バックアップ」をそのまま使う(版を上げる前に写しを取る)
  - 新しいデータは、すべてバックアップの書き出し・読み込みに入れる。古いバックアップ(版7まで)も読み込める
- 5つの段階に分ける。テスト版に反映する前と、main にマージする前に止まる(データの形が変わるので、マージの前に必ず声をかける)
- 決めてほしいことの答えは「決まったこと」の章にある。週の始まりは、アプリ全体で月曜にそろえる

## 前提

- この計画は、`dev`(3e430d9 フェーズ2。main と同じ)のコードを元にしている
- 画面の言葉の「人格」は、今と同じしくみ(`useTerm` の `t()`)で、設定した呼び方に置き換える
- 人格の名前を出すところは、名前ラベル(`AlterNameLabel`)を使う。選ぶための部品(大きな色のボタンなど)と印刷は今までどおり
- 並び替えは、すべて ≡ のドラッグで行う
- 日付・期間(今月・今週・今日・前回の受診日から)の計算は `src/lib/period.ts` を通し、純粋関数にしてテストを書く
- 交代の要約と「誰から誰に」は、フェーズ2で作った関数(`countSwitchPairs`・`guessFromAlterId` など)に、期間の記録だけを渡して使う
- 保存の名前は `src/lib/appTarget.ts` を通す(今回は新しい名前は増えない見込み)
- 医療のアプリではないこと(`SPEC.md` 14章④)は変えない。要約は「傾向を見るためのもの。診断ではない」の注記を付ける

## 1. 受診の記録

### データ(新しいテーブル「受診の記録」)

| 項目 | 説明 |
|---|---|
| id | 一意のID |
| visitedOn | 受診した日('YYYY-MM-DD'。必ず入れる) |
| alterIds | 受診した人格のID(複数。確認したいこと1) |
| staffIds | 話した相手のID(「話した相手の選択肢」の ID。複数。確認したいこと1) |
| createdAt | 記録した日時 |

- 受診の記録は永続データ(1年の自動削除はしない。交代の記録と同じく、長い期間を見られるようにするため)
- 受診した人格・話した相手が、ない人格・ない選択肢を指すバックアップは読み込まない(今までと同じ決まり)

### データ(新しいテーブル「話した相手の選択肢」)

| 項目 | 説明 |
|---|---|
| id | 一意のID |
| name | 名前 |
| order | 並び順 |
| createdAt | 作成日時 |

- 最初の選択肢:主治医/心理士/看護師/ワーカー(版を上げるときと、新しく入れたときに入れる)
- 設定で、追加・名前の変更・並び替え(≡)・削除ができる(一覧は `SPEC.md` 5.1 の共通ルール)
  - 同じ名前は保存できない(「同じ名前の選択肢があります」)
  - 削除は、その選択肢を使っている受診の記録が1件もないときだけ(受診メモの分類と同じ。確認したいこと7)

### 画面

```
治療 › 受診メモ
[診察用の表示]           ← 今と同じ、横いっぱいの大きなボタン
[受診した]  [受診の履歴]  ← 新しく足す(置き場所は確認したいこと2)
```

- 「受診した」を押すと、入力画面が開く
  - 受診した日:最初は今日(論理日)。日付を選べる。今日より後の日は選べない
  - 受診した人格:非表示でない人格+「わからない」から選ぶ(確認したいこと1)
  - 話した相手:選択肢から選ぶ(確認したいこと1)
  - 「保存」で記録する
- 「受診の履歴」で、受診の記録の一覧を開く
  - 新しい順。1行に「10/14(火)・[人格A][人格B]・主治医、心理士」
  - 行を押すと編集画面(日付・人格・話した相手を直せる。「この記録を削除する」は確認を1回出す)
  - 記録がないときは「まだ受診の記録がありません」

## 2. 診察用の表示で、表示する中身と期間を選ぶ

### 画面

```
‹ 戻る   診察用の表示
[メモだけ][メモ+交代記録]           ← 切り替えボタン
期間:[前回の受診日から][今月][今週][今日]
前回の受診日:10月1日  [変える]      ← 「前回の受診日から」のときだけ
受診メモ(2026/10/14)
■ 人格A
【体調】
・…
──────
交代の記録(10/1〜10/14)
要約:12回/人格A 5回・人格B 4回・わからない 3回/多いきっかけ:音 4回・疲れ 3回
詳しい一覧
10/2(金)
 21:30 [人格A] → [人格B] 音
 ...
[文字としてコピー]
```

- 「メモだけ」:今の診察用の表示と同じ中身
- 「メモ+交代記録」:メモの下に、選んだ期間の交代の記録を出す
  - 要約:期間の回数・出た人格ごとの回数(人格の並び順、「わからない」は最後)・多いきっかけ(確認したいこと6)
  - 詳しい一覧:日付ごとに「時刻 [交代前] → [交代した人格] きっかけ」(フェーズ2の一覧と同じ形。推測のままの記録には「(推測)」)
  - 記録がない期間は「この期間の交代の記録はありません」
- 期間
  - 前回の受診日から:いちばん新しい受診の記録の日から今日まで(確認したいこと4)
  - 今月・今週・今日:論理月・論理週(月曜から)・論理日。アプリのほかの画面と同じ区切り
  - 受診の記録が1件もないときは、「前回の受診日から」を押せなくし、「まだ受診の記録がありません」と出して、今月を選んだ状態にする
- 「前回の受診日:○月○日」は直せる(確認したいこと3)
- 「メモだけ/メモ+交代記録」と期間は、アプリを開いている間は最後に選んだほうを覚える(保存はしない。ほかの切り替えと同じ)
- 「文字としてコピー」にも、選んだ中身をそのまま入れる(確認したいこと5)

## データとバックアップへの影響

- データベースの版:7 → 8(更新のお知らせは「データの形が変わる」強めのものになる。`DB_VERSION` を上げると自動で `version.json` に入る)
- 版を上げる前に、移行前の自動バックアップ(`SPEC.md` 18.4)で版7のデータを写す。写しは新しいものに置き換わる(前回の版6の写しは消える)
- 今のデータ(人格・タスク・記録・受診メモなど)は書き換えない。新しいテーブルを2つ足し、話した相手の最初の選択肢を入れるだけ
- バックアップの版番号(`BACKUP_FORMAT_VERSION`)は上げない。受診の記録がない古いファイルは「記録なし」、話した相手の選択肢がないファイルは「最初の4つ」として読み込む
- 受診の記録で受診した人格に入っている人格は、削除できない人格に数える(`SPEC.md` 3.1。確認したいこと8)

## 確認したいこと

1. **受診の記録の項目**
   - 受診した人格は、複数選べる形でよいですか(付き添い・交代しながら受診、などがあるため)。0人(選ばない)でも保存できるようにしますか、それとも「わからない」を選ぶ形にしますか
   - 話した相手も複数選べる形でよいですか。選ばなくても保存できるようにしますか
   - 日付のほかに、ひとことメモの欄は要りますか(例:「薬が変わった」)。おすすめ:今回は入れない(受診メモと役割が重なるため)
2. **「受診した」と「受診の履歴」の置き場所**
   - 案A(おすすめ):受診メモ画面の「診察用の表示」の下に、2つ並べる
   - 案B:「診察用の表示」の画面の中(一番下)に「受診した」を置く(診察が終わったその場で押せる)
   - 受診したときに、まだ話していないメモを自動で「話した」にはしません(今までどおり、メモごとにチェックする)。それでよいですか
3. **「前回の受診日:○月○日」を直す、の意味**
   - 案A(おすすめ):表示の基準の日だけを、その場で変える(受診の記録は変えない。アプリを開いている間だけ覚える)。記録し忘れた受診があったときや、もっと前から見たいときに使う
   - 案B:いちばん新しい受診の記録の日付そのものを直す(受診の履歴の編集と同じ)
4. **「前回の受診日から」に、受診日の当日を入れるか**
   - 受診の記録には時刻がないため、受診日の当日の記録が、受診の前か後かわかりません
   - 案A(おすすめ):当日を入れる(診察のあとに起きた交代を見落とさないため。前回の診察で話した分が少し重なる)
   - 案B:当日を入れず、次の日から
5. **期間が、メモの部分にも効くか**
   - 今の診察用の表示は「まだ話していないメモ全部」を出しています
   - 案A(おすすめ):メモは今までどおり「まだ話していないもの全部」。期間は交代記録の部分だけに効く(話していないメモが期間の外で消えてしまわないように)
   - 案B:メモも、期間の中に書いたものだけにする
   - 「文字としてコピー」にも、交代記録(要約と詳しい一覧)を入れてよいですか
6. **交代記録の要約の中身**
   - 回数(全○回)・出た人格ごとの回数・多いきっかけ、でよいですか
   - 多いきっかけは、回数の多い順に上から3つまで(同じ回数ならきっかけの並び順。「わからない」は入れない)、でよいですか
   - 時間帯ごと(5〜8時など)は入れなくてよいですか(おすすめ:入れない。診察で短く伝えるため。詳しくは交代タブの PDF で見られる)
7. **話した相手の選択肢の設定の置き場所と削除**
   - 案A(おすすめ):「受診の履歴」の画面に「話した相手の設定」の入口を置く
   - 案B:受診メモ画面の「分類の設定」の隣に置く
   - 使っている受診の記録がある選択肢は削除できず、名前の変更はできる(分類と同じ)。非表示は作らない。これでよいですか
8. **人格の削除**:受診の記録で「受診した人格」に入っている人格は、削除できない人格に数えてよいですか(消すと誰が受診したかわからなくなるため)
9. **受診の記録の PDF**:今回は作らない(交代タブの PDF と、診察用の表示の「文字としてコピー」で足りるため)でよいですか

## 決まったこと(2026-10-14)

1. 受診した人格・話した相手は、どちらも複数選べる。どちらにも「わからない」を置く。何も選ばずに保存したときも「わからない」として扱う。ひとことメモの欄は入れない
2. 「受診した」「受診の履歴」は、受診メモ画面の「診察用の表示」の下に2つ並べる(案A)。受診したときに、メモを自動で「話した」にはしない
3. 「前回の受診日」を直すのは、表示の基準の日だけ(案A。受診の記録は変えない)
4. 「前回の受診日から」には、受診日の当日を入れる(案A)
5. 期間は交代記録の部分だけに効かせる(案A。メモは「まだ話していないもの全部」のまま)。「文字としてコピー」にも交代記録を入れる
6. 要約は、全回数・人格ごとの回数・多いきっかけ上位3つ(同じ回数ならきっかけの並び順。「わからない」は入れない)。時間帯は入れない
7. 話した相手の設定の入口は「受診の履歴」の画面(案A)。使っている選択肢は削除できず、名前の変更はできる。非表示は作らない
8. 受診した人格に入っている人格は、削除できない人格に数える
9. 受診の記録の PDF は今回は作らない
10. 週の始まりは、アプリ全体で月曜にそろえる(画面によって週の区切りが違わないように)
    - ToDo の毎週のタスクは、今までどおり月曜始まりのまま変えない
    - フェーズ2で作った交代のカレンダーを、日曜始まりから月曜始まりに変える
    - 診察用の表示の「今週」も月曜始まり
    - 将来「週の始まりを月曜/日曜から選べる設定」を入れるかもしれないので、週の始まりは1か所(`period.ts` の `WEEK_START_DAY`)で決める作りにする

## 週の始まりについて(確かめたこと)

今、月曜始まり(`period.ts` の `toLogicalWeek`)で動いているのは、ToDo の「毎週」のタスクだけ。

- 毎週のタスクの「完了/未完了」の判定(`SPEC.md` 4.2。月曜朝5時に未完了に戻る)
- 取り消しで消す記録の範囲(今週の記録)
- ToDo 画面の「今週」の欄の表示と、前の期間の表示「先週:人格A・水 14:20」
- ほかの画面(服薬・受診メモ・交代・集計)は、週で区切っていない
